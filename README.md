# 星星成长记 · 儿童成长激励系统

面向 5–15 岁孩子的习惯养成工具。**许愿先行 → 完成任务攒星星币 → 攒够兑换**，双货币 + 等级特权驱动长期坚持。

## 一、快速开始

> **第一次部署、手机平板怎么用、怎么备份，请读 [`DEPLOY.md`](DEPLOY.md)。**

```bash
# 首次安装依赖
pip install -r requirements.txt

# 初始化演示数据（首次运行）
python seed.py

# 启动
python run.py              # 本机访问 http://127.0.0.1:8777
python run.py --lan        # 允许手机 / 平板在同一 WiFi 下访问
```

也可以**双击 `start.bat`**，用菜单选择「本机试用」或「手机 / 平板」，
菜单里还有备份、重置演示数据、自检。

**自检（服务启动后另开一个窗口）**

```bash
python smoke_test.py          # 主流程 69 项：任务→打卡→审批→许愿→定价→兑换→核销→错题本
python smoke_test_extra.py    # 扩展模块 49 项：花园 / 番茄钟 / 识字 / 宠物 / 家长学堂
python seed.py --reset        # 把演示数据拨回干净状态（服务占用时会改为清空所有表）
```

`--lan` 会打印一个 `192.168.x.x` 的地址，手机、平板直接打开即可，**不需要联网、不依赖任何 CDN**。


**演示账号**

| 角色 | 昵称 | 登录方式 |
|---|---|---|
| 主家长 | 豆豆爸爸 🦸 | 用户名 `dad` 口令 `1234` |
| 家长 | 豆豆妈妈 👩 | 用户名 `mom` 口令 `1234` |
| 孩子（7 岁） | 豆豆 🐣 | 点头像，口令 `1234` |

两名家长可以同时登录，谁先看到谁审批。以上昵称、头像、用户名、口令以及左上角
品牌名都只是默认值，登录后随时可改（见「账号资料与界面自定义」一节）。

> 登录失败限流：同一账号 **10 分钟内连续输错 6 次**会锁定 5 分钟，提示语已按
> 孩子的口吻写好，不会吓到他。登录成功会同时清零账号与 IP 两个维度的计数——
> 一家人（或走内网穿透时）共用同一个出口 IP，只清账号的话几次手滑就会把全家
> 一起锁在门外。阈值可用环境变量 `KIDS_LOGIN_MAX_FAILS` / `KIDS_LOGIN_WINDOW` /
> `KIDS_LOGIN_LOCK` 调整。

## 三、必须知道的三件事

**1. 改规则不要改代码。** 家长端「管理 → 打开规则编辑器」是一个可视化页面：每日上限填个数字、开关拉一下、等级称号写成表格，点保存**立即生效**。所有内容最终写回 `rules.yaml`。

  - 写入时会**保留文件里的中文注释和原始排版**，不是粗暴地重新生成一遍。
  - 等级门槛改完之后，孩子的等级**当场重算**——否则改了表孩子等级却不动，他会以为系统坏了。
  - 门槛起冲突（比如两级成长值相同）会自动修正为严格递增，第一级固定为 0。
  - 「查看 / 编辑 YAML 原文」保留了完整手写的逃生口。

**2. 星星币与成长值是一致的双货币。** 同一笔收入两个账户同时增加。兑换愿望花掉的是星星币，**成长值和等级永远不清零**——这是孩子不会在第 15 天失去动力的关键。

**2b. 愿望需要多少星星币，由家长定价。** 孩子许愿时只写"想要什么"，不填价格。孩子自己定价两头不讨好：往低了填好快点兑换，往高了填根本攒不到。所以新建的愿望价格是 0（显示"⭐ 星星币待爸爸妈妈定"），家长在「愿望管理」里确认时给出数字，之后还能随时改。没定价的愿望不能兑换，服务端会拦。

**3. 所有加减分只能走 `PointService`。** 孩子端、家长手动、游戏、审批，全部经过同一个入口，每日上限因此无法被任何渠道绕过。

## 四、常见问题

**1. 改了后端代码，页面却没变化（或接口 404）。**

`app/` 下面的 Python 只在**服务启动时**加载一次，改完必须**停掉服务再启动**：
`start.bat` 菜单里退出后重新选 1/2，或者直接关掉那个黑窗口再双击启动。

只刷新浏览器是不够的——刷新只会重新拉 `static/` 里的前端文件。
**前端（js/css）改动刷新即可，后端改动必须重启。** 这是"按钮点了没反应"最常见的原因。

**2. 某个页面点开一片空白。**

先看服务黑窗口里有没有红色报错。多数情况是上一条：路由是新加的，但服务是旧进程，
于是前端按钮已经画出来了，接口却返回 404。重启服务即可。

**3. 登录提示「尝试次数太多了」。**

10 分钟内同一账号连续输错 6 次会锁 5 分钟（防暴力破解，见第一节）。
等一会儿会自动解开，或者重启服务立刻清空计数（计数在内存里，不落盘）。

**4. 想清空重来。**

```
python seed.py --reset
```

会清空所有表并重新写入演示数据。**会清掉真实数据，先备份**（见第五节）。
如果服务正在运行，数据文件删不掉，脚本会自动改成"清空所有表"，效果一样。

**5. 端口 8777 被占用 / 手机连不上。**

端口占用换个端口：`python run.py --lan --port 8788`。
手机连不上多半是 Windows 防火墙，右键管理员运行 `firewall-allow.bat` 加一条入站规则。

**6. 教材打开是空白 / 提示"打不开"。**

先看这本书的状态是不是「下载失败」——教材库里点一下「重试」就行。
下载中断会留下 `.part` 文件，重试是**接着下**，不用从头来。
如果整个书架都是空的，说明还没下过教材：
`python tools/fetch_textbooks.py --preset primary-ym`。

**7. 下载教材很慢或者一直失败。**

GitHub 在国内时通时不通，脚本内置了 6 条镜像并会自动轮换，通常慢一点但能完成。
实在下不动，也可以在教材库里用「🔗 远程地址」填一个能访问的 PDF 直链。

## 五、备份

不要直接复制 `data/kids.db`。数据库是 **WAL 模式**，直接拷文件会丢掉尚未合并的事务。

用 `start.bat` 菜单里的 **`4) 备份数据`**，它会：

- 用 `VACUUM INTO` 生成**一致性快照**，避免 WAL 事务丢失
- 连同孩子上传的**佐证照片**、当前 `rules.yaml`、**教材索引与页数**一起打包
- 输出到 `backups/日期_时间/` 目录

教材 PDF 本体（几百 MB）**不进备份包**——它们随时能重新下载，
换机器时把 `data/` 恢复后重跑 `tools/fetch_textbooks.py` 就行。

**建议每周一次**，或每次调整规则之后一次。恢复方法见 [`DEPLOY.md`](DEPLOY.md)。

### 错题本（分科目汇总 / 打印 / 导出 Word）

| 能力 | 说明 |
|---|---|
| 🏷️ 科目由家长维护 | 管理 → 🏷️ 科目管理，可增删改；删掉的科目不会删题，那些题自动归到「其它」 |
| 🔽 下拉筛选 | 孩子端错题本顶部可按科目筛选 |
| ↕️ 排序 | 最近错的在前 / 错得多的在前 / 我排的顺序（上下箭头手动调） |
| ✍️ 编辑 | 题面、正确答案、我写的答案、错因、知识点、解析都能改 |
| 📊 分科汇总 | 家长端「管理 → 📕 错题汇总」按科目分组，含掌握率、错因分布、近 30 天趋势 |
| 🖨️ 打印练习卷 | 单独打开打印窗口，A4 排版：前面只有题面 + 留白，后面才是答案 |
| 📄 导出 Word | 生成真正的 .docx（手写 OOXML，无第三方依赖），同练习卷版式 |

**间隔复习（艾宾浩斯）**：订正之后按孩子的自评排下次复习 ——
😵 忘了 → 明天再来；😅 有点难 → 退一档；🙂 会了 → 下一档；😎 太简单 → 直接跳两档。
爬到第 2 档才算「已掌握」，所以"当天蒙对"不算学会；同一道题再做错，梯子从头爬。
状态有三档：**待复习 / 复习中 / 已掌握**，首页只提示「今天到期」的题，不会一次堆几十道。

打印/导出的每道题末尾带来源编号（如 `#000012`），孩子做完可以直接回系统里找原题录入结果。

### 教材（本地上传 / 远程地址 / 内置教材库）

| 能力 | 在哪儿 | 说明 |
|---|---|---|
| 📤 上传 PDF | 管理 → 📚 教材库 | 手机或电脑都能传，文件落在 `data/textbooks/`，不出本机 |
| 🔗 远程地址 | 同上 | 填一个 PDF 直链，**默认下载到本机**；也可以只存链接 |
| 📥 内置教材库 | 同上 | 收录 ChinaTextbook 的 1905 本（30.4 GB），挑中的按需下载 |
| 📖 孩子阅读 | 孩子端底栏「📚 教材」 | 自建阅读器：翻页、跳页、缩放、左右滑动，**自动记住读到第几页** |
| ✍️ 布置阅读作业 | 教材库页底部 | 「读第 a–b 页」，孩子点「我读完啦」→ 家长确认 → 走 PointService 加分 |

**为什么不用现成的方案。** 参考的森灵家庭系统是「运行时现场代理 GitHub」：
每次打开都走 `/api/textbooks/proxy` 去拉，缓存没命中就转圈，GitHub 一抽风就报错。
本项目改成 **先落到本地，再从本地读**：

- 目录索引 `data/textbook-catalog.json` 是一次性生成的离线清单，浏览教材**完全不联网**；
- 只有真的点「下载」时才碰网络，而且带 **多镜像轮换 + Range 断点续传 + `.part` 临时文件**；
- 下完之后看书是本地文件，**断网、GitHub 挂了都不影响**。

**关于阅读器。** 用自托管（非 CDN）的 pdf.js 渲染到 canvas，而不是 `<iframe src="x.pdf">`：
iframe 用的是浏览器自带插件，我们拿不到「当前第几页」，而"上次读到第 12 页"
恰恰是这功能对孩子最有用的地方。文件接口支持 HTTP Range，40 MB 的课本翻页也是瞬开。

**下载更多教材**（命令行，不占着网页）：

```
python tools/fetch_textbooks.py --preset primary-ym    # 小学1-6 语文统编+数学人教（24本/449MB）
python tools/fetch_textbooks.py --subject math --grade 一年级
python tools/fetch_textbooks.py --path "小学/语文/统编版/义务教育教科书·语文一年级上册.pdf"
python tools/fetch_textbooks.py --preset primary-ym --dry-run   # 只看清单和体积
```

下载完不用重启：家长一打开教材库，脚本会把本地已有的书自动挂进书架。
